ZERO TO WORKING

Put Flint on any laptop

No jargon, no cloud lock-in, and no mystery spending. You own the checkout, the key, and every commit.

The short versionInstall four ordinary tools, clone the repository, run one setup command, paste one API key, and reload Cursor.
  1. 1

    Install the basics

    Install Cursor, Git, Python 3, and the current Node.js LTS. On Windows, install WSL with Ubuntu and do the terminal steps inside Ubuntu. These are tools on your laptop—not subscriptions to Flint.

  2. 2

    Get an OpenRouter key

    Create your own OpenRouter account, make an API key, and copy it. A key is a password for models. Do not email it, paste it into source code, or commit it to Git.

  3. 3

    Download and install Flint

    Open a terminal, then run these commands one line at a time:

    git clone https://github.com/Devon-ODell/OpenRouterSwarm.git
cd OpenRouterSwarm
./setup.sh

    Run ./setup.sh from inside the OpenRouterSwarm folder. The setup creates an isolated Python environment, runs the checks, packages the extension, and installs it into Cursor when Cursor’s command-line tool is available. If Flint is already set up and you only want to reinstall this extension, run ./cursor-extension/install.sh from that same folder.

  4. 4

    Restart Cursor

    Fully quit Cursor and open it again, then look for Flint in the secondary sidebar. On macOS, quitting means Cursor → Quit Cursor or Cmd+Q, not merely closing the window. Open this Settings page and save your OpenRouter key.

  5. 5

    Use it on a project

    Open a Git project in Cursor. Put the cursor inside a function—or select exact lines—then ask a question below. Use Queue as task when you want tested work prepared on swarm/trunk. Flint never merges that branch into your main branch unless you do it.

Moving to another laptop

Repeat steps 1–4 on the new machine. Clone your project separately, open it in Cursor, and choose its project settings here. Keys are deliberately not copied with Git; save the key once on each laptop.

Your control, plainly stated

Cloud requests go only to the provider you choose. Local providers keep prompts on your own machine. Paid fallback is off unless you enable it, and its cap is visible. The daemon works in its own Git worktrees; you decide whether accepted commits ever reach main.
